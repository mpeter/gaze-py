# gaze-py Audit — 2026-07-12

Scope: performance investigation (why `make quality` in fieldkit-cmd takes
forever) + deep/wide gap audit against the Go gaze implementation.
Method: deterministic surface collection (taxonomies, CLI, config, schema,
detector emissions) on both implementations, then empirical probes against
live code. All findings below were reproduced, not inferred.

## Part 1 — Performance

### P1. Project-docs text re-scanned per side effect (FIXED)

`ClassificationEngine.classify()` concatenated the entire O3 doc-scan text
(fieldkit-cmd: 1,283 md files, ~5.9 MB) onto the per-function docstring and
lowercased + keyword-scanned the blob **for every side effect**. py-spy
showed 96% of runtime in this path (63% in `str.lower` alone).

Fix (this change): scan the invariant docs text for signal keywords **once**
in `__init__`; per-call work is now a keyword scan of the tiny per-function
docstring unioned with the precomputed hit set. Semantics proven identical:

- keywords are alphabetic → none can straddle the old `"\n"` join boundary
- full-output verification: `gazepy crap src/fieldkit/` on fieldkit-cmd,
  old vs new code — **1,337 lines byte-identical, same exit code**

| Metric (fieldkit-cmd, `gazepy crap`) | Before | After |
|---|---|---|
| Wall time | 4:34.97 | **0:22.22** (12.4×) |
| Peak RSS | 515 MB | 424 MB |

### P2. docscan walks excluded directories (OPEN)

`scan_docs()` uses `Path.rglob("*.md")` from the repo root and filters
*after* enumeration — it still descends `.venv/`, `node_modules/`, `.git/`.
Go gaze prunes during the walk (`filepath.SkipDir`, scanner.go:106). Python
burns up to the full 30s `doc_scan_timeout` and then **silently truncates
the doc list**, which changes classification inputs run-to-run (a
determinism problem, not just speed). Fix shape: `os.walk` with in-place
`dirs[:]` pruning against the exclude patterns. 

### P3. astroid call-graph rebuild dominates the test suite (OPEN)

gaze-py's own suite (942 tests) took 2:51; py-spy shows the hotspot is
astroid node construction from `quality/pairing.py`'s transitive call graph
(`_build_astroid_graph`), which `MANAGER.clear_cache()` forces to rebuild
per invocation. Options, in increasing invasiveness: session-scoped astroid
fixture for tests; scope clear_cache() to analyzed paths; make Pass-3
pairing lazy (only when passes 1–2 leave unpaired functions).

### P4. Analysis loop is serial (OPEN, lower priority)

`detect_and_classify()` processes files one at a time. After P1 the crap
path is ~22s on 212 files; a `ProcessPoolExecutor` over files would cut
most of the remainder if wanted. Not worth it before P2/P3.

## Part 2 — Gaps vs Go gaze

### G1. Ten contract-mandated effect types missing from the port (HEADLINE)

This is a **porting-contract violation**, not a discretionary gap. The
authoritative contract (`../gaze/docs/porting/contracts.md`, EC-001) fixes
the tier table at P0=6, P1=11, P2=16, P3=9, P4=6 — **"Total: 48 effect
types"**, stated in bold — and `taxonomy-reference.md` enumerates all 48.
gaze-py implements 38. Missing:

- **ErrorSignal — contract tier P0.** EC-002 ("P0 Zero Tolerance") requires
  zero false negatives on P0 types. A missing P0 type is the most severe
  class of violation the contract defines.
- P1: GeneratorYield, ContainerMutation, StreamOutput
- P2: AsyncGeneratorYield, MetaprogrammingMutation, DescriptorEffect,
  ResourceManagement, ImportSideEffect, MonkeyPatch

Compounding it: **AGENTS.md enshrines the shortfall.** It claims the
contracts' type count is "a documentation bug" and mandates "Tests MUST
assert 38" under gatekeeping protection ("never add, remove, or reclassify
without a constitution amendment"). The contract's own tier table sums to
48 — the 38 figure came from enumerating the *implemented* enum, not the
contract. Per AGENTS.md's own rule ("Any element that contradicts a porting
contract MUST be revised — the contract wins"), the 38-gate itself is the
element that must be revised. Fixing G1 therefore starts with a constitution
amendment to AGENTS.md, not with detector code.

Empirical impact (probe functions, gazepy analyze):

| Probe | Expected | Got |
|---|---|---|
| generator (`yield`) | GeneratorYield | **nothing — function invisible** |
| `os.getcwd = lambda: ...` | MonkeyPatch / GlobalMutation | **nothing** (P0-class false negative) |
| `with open(path) as f` (read) | ResourceManagement / file read | ReturnValue only |
| `sqlite3` execute+commit | DatabaseWrite | **nothing** |
| `subprocess.run` | process spawn | `GoroutineSpawn` (semantically wrong label) |

Detector has 0 references to `ast.Yield` / `ast.YieldFrom` / `ast.Import`.
A Python analyzer that can't see generators, monkeypatching, import-time
effects, or sqlite writes is blind to several of the most common Python
side-effect families.

### G2. Per-effect classification dropped (schema-compat break)

Go classifies each side effect and attaches `classification` per effect in
JSON (schema.go:113). gaze-py's `runner.detect_and_classify()` loops
effects but **overwrites `target.classification` each iteration** — only
the last effect's result survives, on a single per-function slot — and the
JSON emits no per-effect classification at all. The README's "output is
schema-compatible with Go gaze" claim is false on this axis, and any
quality metric keyed on classification inherits iteration-order
arbitrariness for multi-effect functions.

### G3. Runner never passes docstring/class context into classify()

`runner.py` calls `engine.classify(effect, target)` without `docstring`,
`class_bases`, `return_type_hint`, or `receiver_name` — so in the crap/
quality path, Signal 5 sees only project docs (never the function's own
docstring) and Signals 1–2 run without class context. The signals exist
and are tested; the pipeline just doesn't feed them.

### G4. Detection-table gaps (smaller)

- `AtomicOp`, `SyncPoolOp` declared but never emitted (Go-runtime concepts;
  acceptable as schema compat, document as intentional).
- async call effects: `await client.get(url)` → ReturnValue only (no
  network effect; defensible without type info, worth documenting).

### Not gaps (verified parity)

- CLI commands: all 8 (analyze, crap, docscan, init, quality, report,
  schema, self-check) present in both.
- Over-specification scoring: implemented (quality/coverage.py:123).
- Line coverage of gaze-py itself: 95.65%, worst file 76% (report/ai.py).
  The problem is not line coverage — it's the behavioral false negatives
  above, all of which live in "covered" code.

## Recommended order

1. Land P1 (done here) — unblocks fieldkit-cmd `make quality` immediately.
2. G1 constitution amendment + detector work — amend AGENTS.md's 38-type
   gate to the contract's 48, then implement the missing detectors
   (ErrorSignal first — it is P0/EC-002 zero-tolerance; then generators,
   monkeypatch, import, resource management, sqlite). The port isn't a
   credible Python analyzer — nor contract-compliant — without them.
3. G2 + G3 together — per-effect classification carried through models →
   runner → JSON, and thread the docstring/class context into the runner.
4. P2 docscan pruning — small, removes the silent-truncation determinism bug.
5. P3 astroid strategy — biggest lever on gaze-py's own suite time.
