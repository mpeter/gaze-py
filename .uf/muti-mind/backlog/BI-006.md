As a developer running gazepy analyze on code that creates a database connection locally and calls .execute(), .commit(), etc. on it, I want those method calls to be detected as DatabaseWrite, so that the most common Python DB access pattern is correctly scored.

Given a function with conn = sqlite3.connect(path) followed by conn.execute(sql), When gazepy analyze runs, Then DatabaseWrite is emitted for the .execute() call.

Given a function where a DB connection is stored under a DB-hinting name (conn, connection, db, cursor, tx) and .commit() is called, When gazepy analyze runs, Then DatabaseWrite is emitted.

Given with sqlite3.connect(path) as conn: conn.execute(sql), When gazepy analyze runs, Then DatabaseWrite is emitted for both the context manager entry and the .execute() call.

Given .execute() is called on a name that was passed in as a parameter, When gazepy analyze runs, Then the existing param-based detection handles it and Story 5 does not duplicate-emit.
